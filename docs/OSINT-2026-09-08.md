# OSINT used for the laptop and dock audit

Checked 2026-09-08. Local measurements take precedence over generic product claims.

The current public OSINT check was repeated on 2026-09-08. It found ASUS BIOS version 306 listed for UM3406KA with a 2026-07-23 publication date; the laptop already reports `UM3406KA.306`, so no firmware update is justified from version mismatch.

- [ASUS UM3406 technical specifications](https://www.asus.com/us/laptops/for-home/zenbook/asus-zenbook-14-oled-um3406/techspec/): the UM3406 family exposes USB4 Type-C display/PD up to 40 Gb/s and a USB 3.2 Type-C display/PD port up to 10 Gb/s.
- [ASUS UM3406KA manual](https://dlcdnets.asus.com/pub/ASUS/nb/UM3406KA/0409_E24342_UM3406KA_A.pdf?model=UM3406KA): the USB4/PD port is intended for external displays and notes that the adapter can become warm under load.
- [JSAUX RGB Docking Station](https://jsaux.com/products/rgb-docking-station-for-steam-deck): the current page advertises high-refresh DisplayPort/HDMI output and labels VRR as HDMI 2.1 only. The page alone does not establish DisplayPort VRR support for every hardware revision.
- [Linux AMD P-State documentation](https://www.kernel.org/doc/html/latest/admin-guide/pm/amd-pstate.html): AMD-Pstate EPP is a hardware performance hint, and EPP values trade performance bias against power savings; this supports observing the current policy before changing it.
- [WD Linux support](https://support-en.wd.com/app/answers/detailweb/a_id/5242/~/linux-and-unix-support-for-western-digital-retail-products): WD supports physical installation on Linux but delegates Linux software behavior to the OS/vendor, so NVMe health is checked locally instead of assuming a Windows firmware workflow.
- [Omarchy dotfiles manual](https://omarchy.org/manual/dotfiles/): user overrides belong under `~/.config`; stock files under `/usr/share/omarchy` should not be edited, and selective dotfile backup is recommended.
- [Current Omarchy monitor manual](https://github.com/omacom/omarchy/blob/quattro/manual/33-monitors.md): Omarchy's examples place monitor rules in `~/.config/hypr/monitors.lua` and generally recommend 1× scaling for 1080p/1440p displays. This supports testing scale 1.0 for sharpness while retaining 1.6 when larger UI text is preferred.
- [Current Omarchy troubleshooting manual](https://omarchy.org/manual/troubleshooting/): the desktop expects `GDK_SCALE=2` for the laptop's high-density panel and documents the built-in hardware reload paths.
- [Linux kernel HID endpoint patch discussion](https://www.spinics.net/lists/kernel/msg6128124.html): the exact `usbhid` message means the probed HID interface has no interrupt-in endpoint. It supports treating the Wushi device as a USB-interface issue, not as evidence of a DisplayPort failure.
- [ASUS UM3406KA BIOS support](https://www.asus.com/supportonly/um3406ka/helpdesk_bios/): version 306 is listed as the current BIOS entry found during this audit.
